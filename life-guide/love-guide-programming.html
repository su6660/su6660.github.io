API核心概念（类比"API 请求前置校验"）

本阶段核心是建立对方对你的基础兴趣位，类比 API Gateway 在转发请求前的 rate_limit + auth + signature_verify。目标不是"聊出感情"，而是验证双方是否有最低限度的互动意愿，并为首次见面收集 1-2 个可用话题锚点。

  • 输入签名: 对方愿意用带信息量的内容回复（非 "嗯" "哈哈" 可判定为有效）
  • 边界条件: 单次对话不超过 8 轮有效交互，每日消息频率不超过 2 次
  • 成功判定: 对方主动提及私人话题或发布带情绪的内容

Logic实现原理（状态流转）

[陌生态] → 触发: 首次消息引起对方好奇心 → [试探态]
[试探态] → 触发: 对方回复含个人信息 (≥2 句) → [建立态]
[建立态] → 触发: 对方主动问你问题或分享日常 → [邀约准备态]
[邀约准备态] → 触发: 双方话题中出现可落地场景 (都喜欢咖啡/都想去看展) → [初次见面]

异常分支:
[陌生态] --对方无回复--> [丢弃态] (1次无回复视为请求超时，≥2次停止重试)
[试探态] --对方只回"嗯/哈哈"--> 触发: 话题钩子失效，更换话题或放弃

Risk注意事项（编译警告/运行时风险）

  • NPE 空指针风险 — 查户口式提问 ("你哪里人? 你多大? 你做什么工作?")。对方直接断连，因为这是 HR 面试不是社交。类比: 未初始化对象就调用方法抛出 NullPointerException。
  • DOS 拒绝服务风险 — 连续发消息对方不回还继续发。类比: 对 server 发送过多请求触发 rate limit 封禁。
  • Stack Overflow 栈溢出 — 一条消息叠 3 层含义 + 5 个话题点，对方处理不过来直接关闭。
  • Cache Poisoning 缓存污染 — 在没见面之前就把自己包装成完美人设，见面即 crash。类比: 返回错误数据存入对方脑中的缓存。

API核心概念（类比 "JWT Token 签发"）

初次见面的 3 秒内，对方已经在潜意识里签发了一个 "是否愿意继续交互" 的 JWT Token。类比: 服务器收到请求后立即验证 TLS 握手 + 证书完整性。这个 token 的有效期直接决定对方是否会接 Module 2 的调用。

  • 3 秒校验: 微笑 + 眼神接触 0.5-1 秒 + 自然问候 (不是谄媚的鞠躬式问候)
  • 30-60 分钟窗口: 不要超过 90 分钟，留 "意犹未尽" 状态比 "耗尽话题" 重要
  • 成功判定: 对方主动提及 "下次可以..." 或交换新联系方式 (比如加了某平台好友)

Logic实现原理（状态流转）

[物理未知态] → 触发: 3 秒微笑锁定 → [印象建立态]
[印象建立态] → 触发: 30 分钟内双方都有提问 → [信息交换态]
[信息交换态] → 触发: 出现 1 次以上 "同时笑/眼神交汇≥2秒" → [好感确认态]
[好感确认态] → 触发: 提出离场 + 对方表现出不舍 → [进入 Module 2]

异常:
[印象建立态] --对方全程玩手机/敷衍--> [降级态] (本次为 meetup fail，Module0 重来)
[好感确认态] --当场表白/肢体接触过多--> 触发: token 被吊销 (对方认为你越权)

Risk注意事项（运行时风险）

  • CSRF 跨站伪造请求 — 试图在初次见面就越界: 牵手 / 坐很近 / 表白。类比: 你还没拿到 token 就直接提交敏感操作请求，服务器直接 403。
  • Memory Leak 内存泄漏 — 一个人说 50 分钟对方听 10 分钟。自我表达欲失控，对方体验 = 垃圾回收。
  • Race Condition 竞态条件 — 对方说 "我喜欢旅游"，你和对方同时开口。解决方案: 让对方先说，你是 client，对方是 server。

API核心概念（类比 "心跳包 + WebSocket 长连接"）

本阶段目标不是"聊感情"，而是建立双向舒适频率。类比 WebSocket 的心跳机制: 双方定期发 ping/pong 来确认连接仍然存活，但心跳频率过密会浪费资源，过疏会触发超时断连。核心 API 签名: sendContent(message) → expect(response_with_value)

  • 频率建议: 平均每天 1-2 轮有效交互，不连续超过 3 天无话可说
  • 内容策略: 70% 轻松日常 + 20% 共同兴趣 + 10% 适度自我暴露
  • 成功判定: 对方主动发起话题的频率 ≥ 你发起频率的 60%

Logic实现原理（状态流转）

[连接建立态] → 触发: 2 天内有 ≥ 1 次有效对话 → [频率稳定态]
[频率稳定态] → 触发: 对方主动发起 ≥ 2 次/周 → [信任积累态]
[信任积累态] → 触发: 出现"共享笑点"或"私密吐槽" → [进入 Module 3 准备]

异常:
[频率稳定态] → 连续 3 天你发起对方只敷衍 → 触发: 退回到 Module0 重评估
[信任积累态] → 你每天发 5+ 条消息 → 触发: 对方进入 [压力态]，连接降频甚至断开

Risk注意事项

  • Memory Heap 内存溢出 — 永远不做聊天记录审查者，也不把之前聊过的话题拿出来说 "你上次说过..."。对方需要感觉新鲜的连接而不是被盘问。
  • Hotfix 热修复过度 — 对方只回了 "嗯" 你立刻发第二条第三条想救场。类比: 一个 404 错误你连续发 5 个重试请求，server 直接 ban 你 IP。
  • Singleton 单例滥用 — 你把对方当成你唯一的情绪输出端口，每天只跟她聊天。你的社会支持网络越单一，这个系统越脆弱。

API核心概念（类比 "Maven Artifact 发布前的集成测试"）

约会不是"见面聊天"的同义词。它是一个有明确设计意图的产品发布流程。你的核心职责是在 1.5-2 小时内完成三件事: 展示真实的你、验证线下化学反应强度、给对方一个"下次还想出来"的充足理由。

  • 节奏控制: 约会时间 = 45 分钟核心 + 30 分钟活动 + 45 分钟收束。宁可早走不要拖到冷场
  • 成功判定: 对方主动说 "这次好有意思" 或 "下次我们可以..."，且在回家路上主动发消息报平安

Logic实现原理

[约会前准备态] → 触发: 提前 1 天确认行程 + 对方回复确定 → [约会中态]

[暧昧微信号态] → 触发: 结束时拥抱/牵手 (被动) 或 对方说"下次" → [进入 Module 4]

[约会中态] --全程聊工作/生活琐事--> 触发: 对方判定你为"一般朋友"，进入 friendzone 风险

Risk注意事项

  • Scope Creep 范围蔓延 — 一个约会本来只打算 2 小时，结果去了餐厅又去逛街又去看电影。类比: 一个 sprint 不断加 backlog item。结果: 双方精疲力尽 + 话题耗尽 + 没有"下次"的理由。
  • Hard-coded Response 硬编码响应 — 你按网上的"约会话术脚本"一字不差地说。对方感觉像在跟 AI 对话，立刻触发 uncanny valley。
  • Authentication Bypass 认证绕过 — 约会中试图快速升级肢体接触。类比: 直接跳过 OAuth 授权阶段访问敏感数据。对方会产生"你到底是谁"的安全怀疑。

API核心概念（类比 "微服务发现 + 专属通道建立"）

  • Vendor Lock-in 厂商锁定 — 把"要不要成为男女朋友"当作系统上线的唯一目标。类比: 你开发了一个系统却要求对方立刻签 exclusive contract。过程本身就是关系的一部分，不是上线的阻碍。

API核心概念（类比 "SRE 站点可靠性工程"）

系统上线之后，最大的挑战不是开发新功能，而是如何持续运维不崩溃。类比: 从 Web App 发布到 SRE (Site Reliability Engineering) —— 重点从"功能实现"转向"系统稳定性 / 错误预算 / 容量规划"。核心指标: 冲突修复响应时间 (MTTR)、独立社交频度 (SLO)、个人成长速率 (iteration cadence)。

  • 矛盾处理机制: 每次吵架不是 bug，是 feature request —— 暴露了当前模块里没有覆盖到的使用场景。
  • 成功判定: 两个人在一起比分开时更好，且个人成长速度 ≥ 单身时的 80%

Logic实现原理

[蜜月期] → 触发: 新鲜感衰减 (12-18 个月) → [磨合期]
[磨合期] → 触发: 冲突解决机制建立 + 双方仍保持独立 → [稳定承诺期]
[磨合期] → 触发: 冲突后没有修复 + 一方逐渐失去独立性 → [系统降级/崩溃 (breakup)]

稳定期日常运维:
- 每周 1 次 check-in (简短的 "你这一周怎么样")
- 每月 1 次新的共同经历 (新餐厅/新活动)
- 每季度 1 次"关系审计" (有没有什么让你不舒服我没注意到的)

Risk注意事项

  • Feature Creep 特性蔓延 —— "为什么别人男朋友能做到你不行 / 为什么他们每周年都去冰岛"。你的系统不需要支持 world + wife/husband 两个实例，只需要支持你们俩。
  • Technical Debt 技术债 —— "这次吵架我忍了算了" / "她生气了我先不说话，等她自己好"。所有没被处理的矛盾会在未来以 10x 威力爆发。类比: 一个没写 test 的模块上线 3 个月后导致生产事故。
  • Monitoring Blind Spot 监控盲区 —— 只盯着"有没有吵架"而不关心"有没有开心的时候"。关系的健康度不是 absence of problems，而是 presence of joy。
  • Single Point of Failure 单点故障 —— 你的全部社交 / 情绪 / 生活重心都集中在对方身上。一旦关系出问题，你整个系统就 crash。

阶段跳转预警表 (API Cross-version Calls)
跳过前置模块直接调用高层 API 的风险评估

类比: 你从 v0.1 的 codebase 直接调用 v2.0 的 API，中间所有 breaking changes 都没经过 migration，生产环境 crash 是迟早的事。以下是常见的"越级跳转"场景和对应的风险等级。

源模块 目标模块 风险等级 典型场景与后果
0 线上预热 5 确定关系 Critical 加好友聊了 3 天就表白。后果: 对方判定你 romantic maturity = 0，进入永久黑名单。
1 初次见面 5 身体亲密 Critical 第一次见面就试图亲吻。后果: 触发对方安全警报，consent failure，report to friend zone。
2 日常聊天 3 正式约会 High 没见面过就说 "你做我女朋友吧"。后果: 对方只能依据微信印象做决定，而微信印象永远比本人单薄 50%。
3 正式约会 4 关系深化 Medium 约了一次会就开始查岗、问行程、跟其他异性吃醋。后果: 还没建立信任就触发 boundary breach。
4 关系深化 5 确定关系 Medium 暧昧 3 个月以上还不定关系，但又要求对方排他。后果: 对方开始怀疑你的 intent，要么撤退要么被逼出关系定义但基础不牢。
5 确定关系 6 长期稳定 Medium 刚在一起就要求"结婚""生孩子""见父母"。后果: 对方产生 commitment pressure，进入 [评估态]。
0 线上预热 1 初次见面 Low 聊了 2 天就约见面 —— 只要双方话题密度够，属于正常节奏。Module 0 的目标就是 Module 1 的入口。
