讲座笔记：本地部署智能体（20261031）

一句话总结

这场讲座的主线是「用最低成本把 AI 变成可复用的生产工具」：先用 Agnes 平台拿到 API，再用长期提示词约束 AI 的行为，最后用脚本和自动化流程把重复工作固化下来。

讲座信息

  • 日期：2026-10-31
  • 讲师：熊瑞
  • 地点：和平假日大酒店
  • 主题：本地部署智能体 / 0 成本本地实战部署

核心结论

  1. 用 Agnes 创建 API，把大模型能力接进自己的程序，而不是只在网页里聊天。
  2. 先写长期提示词，把行为规则固定下来，再谈具体任务。
  3. 用 Agnes 的 API 做视频，配合提示词生成内容。
  4. 让 AI 自动化流程，减少人工搬运。
  5. 用 .bat 文件简化工作流程，把重复动作变成双击即执行。

内容梳理

1. 平台与入口

笔记中记录的工具与地址集中在 Agnes 生态：

  • Agnes 文档站：https://www.agnes-ai.cn/zh-Hans/docs/overview，笔记标注「做视频不用钱」。
  • API Key 管理：https://platform.agnes-ai.cn/settings/apiKeys。
  • 视频模型地址：https://www.agnes-ai.cn/zh-Hans/docs/agnes-30-flash。
  • 大模型排行榜：https://aihot.news/leaderboard。
  • 智能体平台：笔记写作 telegent / teleageent，并给出 teleai.com.cn，应指 TeleAI 的智能体平台，具体名称建议以官网为准。
  • 笔记还提到「用 DeepSeek 来操作 wubuuy 和 telegram」，wubuuy 疑为速记误差，待补。

3. 长期提示词「铁律」

笔记中抄录了一套全局规则，属于讲座中强调的最高优先级设定：

  1. 改文件前必须备份：在项目根目录建 .backup，按模块、功能、时间打 .bak，无例外。
  2. 版本号递增：正式项目每次对话以 0.0.01 递增，临时文件不算；有数据库写数据库，没有就写 JSON。
  3. 服务启停交给用户：智能体只提示；确需代操作时设置监听机制，等待不超过 3 分钟。
  4. 有依赖的调用必须串行：并行只用于完全独立的操作，单批不超过 2 个。
  5. 不确定就直说「不确定」，靠经验判断时必须写明「这是经验判断」；每次回答末尾说明哪些确定、哪些需要验证。

这套规则的价值不在技术，而在把 AI 的不确定性显式化，降低误改文件和假信息带来的风险。

4. 附：如何提出一个好问题

笔记后半段粘贴了一段方法论，核心是四个要素：

  • 差距明确：说得清自己不知道什么，而不是「怎么学好英语」这种糊成一片的问题。
  • 带语境：目的、已知条件、已经试过什么。
  • 答案可判定：能说清什么样的回答算答对。
  • 有后果：拿到答案后行动会改变，否则那不是问题。

操作上分五步：先写目标再写问题（警惕 XY 问题）→ 把大困惑拆成小缺口 → 交代「要达成什么、已知道什么、试过什么」→ 预演答案 → 迭代修正。作者也明确标注：四要素分析属逻辑推论，五步法属经验判断。

可以马上做的事

  • 注册 Agnes 并生成一个 API Key，跑通一次对话请求。
  • 把「长期提示词铁律」落到自己的项目里，建立 .backup 目录约定。
  • 用讲座给的提示词模板，做一个最小的「对话 + 图形 + 视频」Web 应用。
  • 把每天重复的 2~3 个操作写成 .bat，先自动化最短的那条链路。
