讲座笔记：本地部署大模型入门（20261104）

发表于2026-11-16|更新于2026-11-16
|阅读量:

本文由现场速记整理，不是讲座逐字稿。笔记以关键词为主，解释部分为结合上下文的整理。

一句话总结

本地部署大模型只需要搞懂四件事：参数决定能力，量化决定体积，显存决定能不能跑，推理速度决定好不好用。先用 LM Studio 或 Ollama 跑通一个 7B 级模型，再谈优化。

讲座信息

  • 日期：2026-11-04
  • 讲师：熊瑞
  • 主题：本地部署大模型 / AI 开发

四个核心概念

概念 含义 现场提到的点
参数量 模型规模，常见 0.8B、7B、27B 笔记记有「6B」
量化 用更低精度压缩权重，如 Q4 「量化 Q4」
显存 决定模型能否完整加载 现场以此判断机器能跑多大模型
推理速度 每秒生成多少 token 「token 速度」是体感关键

一个粗略的经验：Q4 量化下，模型权重占用约为「参数量 × 0.60.7 GB」。7B 大约 45GB，14B 约 9~10GB，32B 约 20GB。再加上上下文缓存，显存要留出余量。

工具与模型

  • Ollama：命令行友好，一条命令拉模型，适合做自动化与接口调用。
  • LM Studio：图形界面，适合选模型、看参数、快速试聊，自带本地 API。
  • 笔记提到「qwen3.8:27b 好用」，型号表述可能有误，实际常见的是 Qwen3 系列不同尺寸，引用前需核实。
  • 现场演示环境已部署 Qwen3.5-0.8B，属于极小模型，适合验证链路，不适合承担正式任务。

现场练习：做一个 LLM 对话程序

笔记记录的要求是：

这个练习的价值在于把三件事串起来：

  1. 本地模型服务：LM Studio 启动本地 API，监听端口。
  2. 后端：任意 Web 框架转发请求，管理对话历史。
  3. 前端：输入框 + 消息列表，流式输出体验更好。

链路跑通后，换模型只需要改配置里的模型名，不需要改代码——这也是本地部署相对云 API 的最大好处：模型可替换、数据不出本机。

选型建议

  • 只想体验：LM Studio 下载 7B Q4 模型，直接聊。
  • 要接自己的程序：Ollama + 本地 HTTP API，脚本化最省事。
  • 要做知识库：本地模型 + 向量库 + RAG，先确认显存能撑住上下文。
  • 要长期跑服务：关注显存占用、并发数和散热，别用笔记本长时间满载。

可以马上做的事

  • 用 LM Studio 跑通一个 7B Q4 模型，记录首字延迟和每秒 token 数。
  • 用 Ollama 拉同一个模型，对比两者体验差异。
  • 写一个最小 Web 对话页面，接本地 API。
  • 记录自己机器的显存上限，形成「能跑多大模型」的清单。

笔记完整度

  • 现场演示的具体框架、端口、代码未记录。
  • 「qwen3.8:27b」型号疑似速记误差。
  • 不同量化等级的质量对比没有记录，属于值得补做的实验。
